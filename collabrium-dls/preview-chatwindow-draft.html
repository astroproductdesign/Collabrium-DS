Chat window AI Native

Draft preview only — nothing here is committed to DESIGN-SYSTEM.md, tokens.css, components.css, or preview.html yet. Class prefix .c-chat*. This is the expanded form of the Prompt input bar; click either trigger below to open it.

Notes for review — please read before assessing the UI

  • Part 0 skipped. No existing .c-chat* code was found anywhere in the codebase (components.css, preview.html, or any surviving draft file) — so there was nothing to rename or delete. Every name below is already final.
  • .c-fpill doesn't exist. The real filter-chip component is .c-chip.c-chip-filter (with .is-active / .is-disabled), documented under Chip. Used that directly for the pillar filter instead.
  • Toolbar button size correction. The Floating bar's toolbar buttons are already the real c-btn-icon.c-btn-sm recipe, which is 32×32px in the shipped CSS — not 36px as the brief assumed. So there's no 36→32 reduction for the Inline composer; both variants share the same 32×32 buttons, keeping the "real Button classes, no bespoke sizing" rule intact.
  • Pillars use the real product names already documented under Logo (CollabSales/Gold, CollabStudio/Fire, CollabContent/Wood, CollabInfluencers/Earth) rather than invented placeholders. CollabInfluencers is shown with zero conversations, demonstrating the disabled/empty pillar state.
  • Footer copy tension, as flagged in the brief: shipped verbatim as "AI can make mistakes. Please double-check responses." — against this system's own content rule ("skip please — UI isn't asking a favor"), which would give "AI can make mistakes. Double-check responses." Flagging rather than silently resolving either way.
  • Single-column breakpoint is implemented as a CSS container query on the shell's own width (not the viewport) — the spec's own reasoning ("the shell is narrower than a rail plus a readable thread") is about the shell, which can be narrower than the window at its `min(1200px, 100vw-48px)` cap.
  • .c-account-menu-item doesn't exist either. DESIGN-SYSTEM.md's own App Shell section explicitly lists an account menu as a deferred, not-yet-built requirement ("if notifications or an account menu become a real requirement, that's a spec change"). The More options menu's row recipe below is a new .c-chat-menu-item, built from the real popover shell already used by Filters/Dept switcher/Search dropdown (shadow-3, radius-md, Neutral-3 border, Neutral-1 fill, spacing-4 padding) plus this brief's own 36px row spec — not a reuse of something that isn't there.
  • More options menu contents are unconfirmed — Retry/Share/Report, shipped as proposed per the brief, not settled.
  • Jump to present demo-only additions, not part of the shipped component: a fixed "Demo: simulate incoming message" button (bottom-right of this page) appends a message to the open window's thread so the pin/detach/has-new/announce behavior is actually testable without a real streaming backend; and a minimal Send handler (click or Enter in the composer) was wired up purely so "send force-scrolls and re-pins" is demonstrable — no reply is generated. In the static "shown outright" copy below, the jump button is forced to .is-visible.has-new so both states are visible without scripting anything.
  • New: rail toggle for the single-column/mobile state. Below 820px of the shell's own width, the rail no longer just disappears — a Ghost icon-only button (.c-chat-rail-toggle, ph ph-sidebar-simple, Tier 1 Regular — "expand/collapse" is one of Iconography's own Tier 1 examples) appears at the right edge of the header, same row as the title, using the space-between the header already had reserved for exactly this ("a right-aligned control would rejoin," per the original Do/Don't). Clicking it slides the rail in as an overlay drawer (288px, capped at 85% width, shadow-4, no more border-right) over a scrim (.c-chat-rail-scrim) rather than revealing it in-flow — closes via the scrim, the same toggle, Escape, or selecting a conversation (a pillar chip deliberately does not close it, same reasoning as message actions' own Do/Don't elsewhere). Delegated and shell-relative (not id-scoped), so it works identically across the real interactive modal and every static reference render below without needing unique ids on each. Two real bugs caught while building this, the second one only after you asked whether the composer should be dimmed too — it visibly wasn't, and a screenshot doesn't tell you why. (1) The rail had never needed its own background — on the desktop column it just sat in front of nothing. As an overlay it needs background: var(--color-neutral-1) explicitly, or the main content bleeds through underneath it. (2) The scrim was correctly reaching opacity 1 but the composer still painted above it regardless of how high the scrim's z-index went or which DOM order they were in — brute-forcing the scrim to z-index 9999 changed nothing. The real cause: .c-chat-main is a CSS grid item with no position/z-index of its own, which left its .c-prompt-bar-surface descendant's own z-index: 10 in an ambiguous stacking relationship with a later sibling's z-index. Giving .c-chat-main an explicit position: relative; z-index: 1 (lower than the scrim's 20) put it back into a directly comparable stacking context, and the scrim started winning immediately. Confirmed by temporarily swapping the scrim to solid opaque red — before the fix it showed the composer punching a clean hole through it; after, full coverage.
