Draft — not in the system yet

Format card

A catalogue tile for an ad-format library: one card per format, each showing a live miniature of how the unit behaves on a page, what it is for, and what it costs to run. Built entirely on tokens.css and components.css as they ship — nothing in either file has been edited.

Use case

Media planners pick formats from a list of forty-odd options whose names mean nothing until you have seen one run. A table of names and sizes does not tell you what a “3D Float-flip” is; a still screenshot barely does better, because the whole difference between one format and the next is what happens over three seconds. This card's job is to make that difference visible before anyone opens a spec sheet.

Use it when

  • The reader is choosing between formats they cannot be assumed to know by name.
  • Behaviour over time is the distinguishing feature — expand, flip, fill, stick.
  • A separate control on the page collects across cards — a compare tray, an “Add 3 to brief” action. That is what earns the compare toggle; without somewhere for the additions to go, it is a dead control.

Don't use it when

  • The reader already knows exactly which format they want — a Table is faster to scan and sorts by size and benchmark, which this cannot.
  • There is nothing to animate. A card whose preview never moves is a base Card with a picture in it, and should be one.
  • Fewer than about four formats are on offer. A grid of two is a decision that should have been a pair of radio buttons.

Where it sits in the system. This is a Card variant, not a new component family — it extends .c-card, .c-card-interactive and .c-card-selectable and adds three parts they do not have: the preview stage, the title row's tag slot, and the rest/spec swap. It takes the Card grid contract unmodified (auto-fill + minmax, align-items:stretch, height:100%), with its own min-width floor of 300px against the base Card's 240.

The component

Hover or tab into a card to play its preview and swap the tagline for the spec. Press + in the top-left corner to add a format to the compare set — the chip fills Obsidian and its glyph becomes a check, and the count below is the tray that justifies the control existing at all. Press it again to remove.

Anatomy

Five parts. Two of them (the checkbox and the card shell) are existing components used verbatim; three are new.

#PartSpec
1Preview stage
.c-format-stage		New. 16:10, full-bleed to the card's inner edge, canvas-warm ground under a Neutral-1 page mock at radius-sm + shadow-1. Bleeds rather than insets because an inset stage needs a nested radius of radius-lg − spacing-16 = 4px, and 4px is not a token — bleeding lets it take the card's own radius-lg and invent no new shape. Decorative: aria-hidden="true", and the format's name and behaviour are carried in text below it.
2Compare toggle
.c-format-compare		Existing components, new arrangement. A real Button — .c-btn.c-btn-icon.c-btn-sm for the 32×32 box, Secondary for the resting white chip and Primary for the Obsidian fill, the two variants simply swapped on state so both poses are the system's own. Circle is the single override, following the precedent .c-prompt-bar-mark already sets for a round icon button. ph-plus → ph-check, both Tier 1, Regular. Top-left, spacing-16 inset, revealed on hover, on focus, and whenever it is on. Measured: check on Obsidian 14.14:1, plus on white 20.03:1.
3Play hint
.c-format-hint		New, and conditional. Renders only under @media (pointer:coarse). A touch device has no hover, so without it the preview simply never moves and the card reads as broken rather than as resting. On a fine pointer it is suppressed — a label telling you to do the thing you are already doing is noise.
4Title row
.c-format-titlerow		New container, existing contents. Card's own h5 type token for the title, and the real Tag component for the family. The title is an <a> with a stretched ::after covering the card — that is what makes the whole card clickable, without a role="button" wrapper. The row fills the card's full content width: title hard left, tag hard right, title taking the slack so the tag pins to the edge whatever the name's length.
5Rest / spec swap
.c-format-swap		New. Two blocks stacked in one grid cell, cross-fading on duration-base. At rest: description (body2/Neutral-5) + funnel-stage line (caption, Title Case — no transform, so the copy's own capitalisation is what renders). On hover or focus-within: Objective, Sizes, Benchmark as a two-column <dl> — label and value on one line, the label column auto-sized to the longest label so the values align down the card. The block takes the card's remaining height, so the eyebrow and the spec's last row both land on the card's bottom edge — and since the grid stretches every card to the row's tallest, that edge is one line across the row. Both halves stay in the DOM and in the accessibility tree; only the paint swaps. Under pointer:coarse it stops being a swap and becomes two stacked blocks.

Purple is the one family the system cannot dress yet. --color-purple is a real token and the palette lists “secondary tags” among its sanctioned uses, so a purple tag is on-spec — but there is no --color-purple-bg, because the -bg tint scale is elemental and purple is not an element. Content rules

FieldRule
SizesComma-separated, ascending by area, always. Held as structured data and sorted at render, not typed as a string — an ordering rule that depends on whoever typed the list is not a rule. An expandable sorts on its collapsed size, because that is the slot it occupies on the page, and carries its expanded size with it (300×250 → 300×600). An aspect ratio has no area, so it sorts on the ratio, running portrait → square → landscape.
BenchmarkA figure with its unit (0.42% CTR, 68% VTR) or the phrase Not published — never blank, and never a zero standing in for “unknown”.
FamilyTag label, 24 characters maximum per Badge & Tag's own authoring limit. The component never truncates; a longer family name gets rewritten.

Why the preview rests. Twelve cards all animating at once is a grid nobody can read, and it is a battery cost on a page that is mostly being browsed. Each stage plays only while the card is hovered, focused within, or tapped — driven by a single --play custom property flipped between paused and running, so every format's animation obeys one switch rather than each one wiring its own.

No raw values, per Component Rule 3. The two exceptions are called out below and both are derived from tokens rather than chosen.

Motion--duration-base + --ease-standard swap; --duration-fast compare-toggle reveal and fill. Each preview takes its family's own elemental curve where one applies — --ease-morph flip, --ease-flare spin (Fire), --ease-settle in-feed arrival (Earth), --ease-flow sticky page travel (Water)
Family tags.c-tag-water / -fire / -wood / -earth / -gold as they ship, plus a local -purple built to the same recipe

Derived, not invented: the stage's inner radius is calc(var(--radius-lg) − var(--fc-bw)) — the inside edge of the card's own border, which moves correctly when Selected swaps 1px for 2px. The wireframe's 3–6px bar heights inside the page mock are sub-token because the mock is a drawing of a page at ~12% scale, not a UI surface; treating them as spacing tokens would be a category error.

Open questions before this goes in

1. Tag contrast fails AA — and this is a pre-existing system issue, not a draft one. Component Rule 5 says contrast is checked, not assumed, so I measured all five Tag variants as they ship in components.css: element colour on that element's own -bg tint, at caption size (12px, weight 700 — body text, so the 4.5:1 floor applies).

TagPairMeasured4.5:1
Water#1473E6 on #E8F1FD3.99:1fails
Fire#FF5825 on #FFEEE92.80:1fails
Wood#FF7A90 on #FFF2F42.28:1fails
Earth#00C26E on #E6F9F12.15:1fails
Gold#FFA425 on #FFF6E91.85:1fails

Badge already solves this for two of its variants — its Success and Warning text are documented as “darkened for AA”. Tag never got the same treatment. The fix is the same one: a darkened text step per element, dot and fill unchanged. That is a components.css change and is not in this draft, because you asked me not to touch the system files. The draft uses Tag exactly as it ships so the gap stays visible rather than being papered over here.

2. Is a format family really a Tag? Half-answered. Badge & Tag defines Tag as “labels which element/department owns something”, and a format family is a taxonomy, not an owner — every format here is owned by CollabMedia, so colouring by owner would make all six cards Water and say nothing.

The mapping is now fixed and recorded (see Families, above), which settles the stability half: the colours can no longer drift card to card. What is still open is the definition — DESIGN-SYSTEM.md needs Tag widened to “ownership or classification” for this to be legal rather than merely consistent, and it needs the purple variant that the sixth family requires. Both are components.css/spec changes and neither is in this draft.

2b. This card's compare control diverges from Card Selectable, deliberately — and the system has to record it. DESIGN-SYSTEM.md:2282 specifies an 18×18 Checkbox at the card's top-right. This one is a round +/✓ Button at the top-left. Two departures, two reasons:

Position. The rule's own justification is “the exact same position and recipe as Profile card's” — and Profile card puts it top-right because its top-left is occupied by the avatar. This card has no such constraint, and it has the opposite one: the page mock's ad rail is top-right, so the documented position lands the control on the one thing the preview exists to show. Measured, it clipped the ad unit by 6×1px on three of the four formats. Top-left covers a skeleton line instead. Worth noting the system is not uniform here anyway — Table pins its bulk-select checkbox left, first column.

Control. A checkbox says this one is included; a + says put this somewhere. With a compare tray as the destination, add/remove is the truer verb pair. It is built from the real Button component in both poses, so nothing here is bespoke — but it is still a second convention for “collect this into a set”, and the fix is to write it down: either widen Card Selectable to cover a collect-style control and a left-hand position, or add a Card Collectable variant beside it. Not decided in this draft.

One contrast caveat, stated precisely: the resting chip's 1px Neutral-3 border measures 1.43:1 against the white page mock, under the 3:1 UI floor. It passes only because the boundary is not what identifies the control — the + glyph is, at 20.03:1. If the chip ever loses its glyph, the border has to darken.

3. The system has no screen-reader-only utility. This draft no longer needs one — the compare toggle carries a real aria-label — but the gap is still there, and several existing components work around it individually. Worth adding once to components.css.

4. Benchmark is sometimes “Not published”. Rendering an empty value as a phrase is right, but it means the Sizes row and the Benchmark row carry different kinds of fact at the same weight. If the benchmark is usually missing, it should probably be a Badge (a status) rather than a spec value.
