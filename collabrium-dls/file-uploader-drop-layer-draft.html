Page drop layer

A drop target the size of the page. It is invisible until someone drags a file over the page, then it veils the layout and says "Drop the brief to start". Dropping a brief checks it, shows "Reading the brief…" for a moment, and hands the file to the page, which starts the campaign with Collab AI. It ports Sales Home's "Drop-a-brief" layer (scan item #17) as a variant of the shipped FileUploader: .c-uploader-page-drop. Only the COMPONENT CSS block is meant for components.css. Everything with the sc- prefix is showcase scaffolding, and k- classes are the "before" copied from the scan.

What already ships, and what is actually new

FileUploader ships drag-and-drop, but only inside its own box. This variant covers the page, appears only during a drag, and hands off to the host. It reuses everything it can. While checking, three gaps turned up in the shipped FileUploader that change what can be reused:

Scope: whole window to detect, main pane to aim

Recommendation: the whole window listens for the drag and accepts the drop, and the veil covers everything, sidebar included. The dashed target and its message sit over the main pane (App Shell's Content region), not the sidebar.

  • Why detect on the whole window: the layer appears wherever the drag enters, so it has to accept the drop wherever it ends. If a brief released 20px to the left, over the sidebar, either did nothing or opened in the browser tab, that would be a trap.
  • Why aim at the main pane: the campaign opens in the main pane, so that is where the eye goes. Centring the message on the full window would put it under the sidebar's edge on wide screens. The sidebar is navigation and has nothing to do with the drop.
  • How: the host sets --c-uploader-page-drop-start to the sidebar's current width (expanded or collapsed), on the layer or on any ancestor. When the sidebar is off-canvas (under 768px), it is 0.
  • Region use: the same component with .is-contained covers just one positioned container (a panel or a modal body), with that container as the drag zone. The demos on this page use that mode, so the "page" is a contained stage rather than your real window.

Anatomy

1 2 3 4 5
  1. Veil: .c-uploader-page-drop, the root. It is fixed to the viewport (or absolute with .is-contained), with an 88% Neutral-2 fill over everything, sidebar included. It is aria-hidden="true" and never focusable. While it is showing, it catches pointer events so the drag events land on it.
  2. Target: .c-uploader-page-drop-target, inset spacing-16, with its start edge pushed past --c-uploader-page-drop-start. It has a 2px dashed Obsidian border at radius-lg, which turns Red while invalid and solid Neutral-3 once dropped.
  3. Icon: .c-uploader-page-drop-icon, icon-lg, Tier 2 Fill, Neutral-9. It is ph-file-arrow-down while dragging and ph-file-x (Red) while invalid. While reading, .c-uploader-page-drop-spinner (ph-spinner-gap, Regular, Neutral-5) takes its place.
  4. Title: .c-uploader-page-drop-title, h5, Neutral-9. "Drop the brief to start", then the invalid reason, then "Reading the brief…".
  5. Hint: the shipped .c-uploader-hint, caption, Neutral-5. "Collab AI reads it and sets up the campaign." While reading, the shipped .c-uploader-row takes its place to show the dropped file.

Class API

Class / hookWhat it is
.c-uploader-page-dropRoot and veil. One per page, a direct child of <body>. Always aria-hidden="true".
.is-dragging / .is-invalid / .is-readingState, on the root, set by the controller only, one at a time. No class means hidden.
.is-containedModifier: absolute instead of fixed, for a region. The container must be positioned.
--c-uploader-page-drop-startHost hook: width of the non-target strip at the inline start (the sidebar). Default 0.
.c-uploader-page-drop-targetThe dashed frame. Holds the three message groups.
.c-uploader-page-drop-msg + -msg-drag / -msg-invalid / -msg-readingOne group per state. CSS shows the one that matches the root state, so swapping state never rewrites markup (except the invalid reason and the file row, which the controller fills in).
.c-uploader-page-drop-icon, -spinner, -titleParts. The hint and file row are the shipped .c-uploader-hint and .c-uploader-row.

Controller contract (for hosts)

const drop = createPageDrop({
  layer:     document.querySelector('.c-uploader-page-drop'),
  zone:      window,                    // or the region element, with .is-contained
  accept:    BRIEF_TYPES,               // ext + MIME list (see Validation)
  maxBytes:  25 * 1024 * 1024,
  multiple:  false,
  onDrop:    file => host.startCampaignFromBrief(file),  // returns a Promise.
             // Host opens its surface, moves focus to its heading, then resolves.
             // The layer stays in "reading" until then, and hides after.
  onError:   (code, info) => host.showDropErrorToast(code, info) // 'type' | 'size' | 'count' | 'empty' | 'read'
});
drop.take(fileList);   // the visible "Upload a brief" button calls this too: one path
drop.disable();        // while any Modal / Tutorial / sheet is open
drop.enable();
drop.destroy();

The AI hand-off lives entirely in onDrop. The component knows nothing about campaigns, Collab AI or routing.

Behaviour

RuleBehaviour
Files onlyThe layer reacts only when dataTransfer.types includes "Files". Text, link and image-URL drags are ignored completely: no layer and no preventDefault, so dropping text into an input still works.
Not from this pageA drag that starts inside the page (dragstart on the document, such as dragging an <img> or a sortable row) sets an "internal" flag until dragend, and the layer ignores it. In Chrome, dragging a page image also carries "Files".
No flickerThree guards. (1) While it is showing, the layer catches pointer events and its children don't, so almost every enter and leave lands on one element. (2) A depth counter goes up on dragenter and down on dragleave, and the layer only hides at 0. (3) When relatedTarget is set and lies outside the zone, the layer hides at once. When it is null and the pointer is at the window edge (in window mode), the drag has left the window. Safari often reports null everywhere, so the counter is the main rule and relatedTarget is only a shortcut.
Watchdogdragover keeps firing while a drag is over the zone, even with the pointer held still (about every 50ms in Chrome; the HTML spec allows gaps of up to 550ms, 350ms ±200ms). If none arrives for 1000ms, the drag has ended somewhere the page couldn't see (cancelled over another app, or a missed dragleave), so the layer resets. This is what stops it getting stuck on.
DismissDragging out of the window (counter reaches 0) hides it. Escape hides it and ignores the rest of that drag. Note that during a real OS file drag, most browsers send Escape to the OS, which cancels the drag, so the page gets dragleave instead. The key handler is a backstop for that, and for stuck states. A hidden tab also resets it.
Never opens the fileA guard on window dragover and drop calls preventDefault() on every Files drag the layer didn't already handle (and sets dropEffect = "none" there). So the browser never navigates to a dropped file, even when the layer is disabled or the zone is a region.
Invalid while draggingBest effort. If dataTransfer.items is readable during the drag (Chrome, Edge, Firefox) and holds 2+ files, or one file whose MIME type is known and not accepted, the layer shows .is-invalid with the reason, and dropEffect = "none" so the cursor shows "not allowed" and releasing does nothing. If Safari exposes no details, or the MIME type is empty, the layer shows the normal state and the check runs on drop. Size can only be checked on drop.
DropValidate (see below). On failure, hide the layer and call onError; the host shows a Danger Toast. On success, show .is-reading with the file row and call onDrop(file). When the host's promise resolves, the layer hides. If it rejects, the layer hides and onError('read') fires.
Reading → hand-offInside onDrop the host opens whatever it opens (Sales Home: the start sheet, prefilled by Collab AI), moves focus to that surface's heading, and resolves. The layer fades out over it. The component has no minimum time; the "moment" is the host's real work. The demo waits 1.6s.
One path indrop.take(files) is also what the visible "Upload a brief" button calls after its file picker, so typed and dropped briefs get the same checks, the same reading moment and the same hand-off.
Off while something is openThe host calls disable() while any Modal, Tutorial or sheet is open, and while reading. A brief dropped behind a dialog would start something the user can't see. The window guard still stops the file opening.
No competing zonesA page with a page drop layer offers a Button as its visible fallback, not a second inline .c-uploader-zone, so two drop targets never compete for the same drag.
TouchPhones have no file drag, so the layer simply never appears there. On an iPad, dragging from Files in Split View works and behaves exactly as on desktop.

Validation and error copy

FileUploader ships no rules or messages to reuse (Gap 1), so these are proposed here for briefs. They are written to Toast's limits (title up to 50 characters, message up to 100) and shown in the shipped Danger Toast, which stays until it is dismissed. Its action slot holds "Choose a file", which opens the same picker as the page's Upload button.

Accessibility

Never the only way inDrag and drop needs a pointer. A page that uses this layer must keep a visible, keyboard-reachable way to upload a brief: a shipped Button ("Upload a brief") that opens a file picker and calls the same take(). The shipped FileUploader zone can't fill this role until it becomes a real control (Gap 2).
Decoration onlyThe layer is aria-hidden="true" in every state, has nothing focusable, and never takes or traps focus. Nobody who can't see it can drag onto it, so there is nothing to announce during the drag.
No live regionsThe component adds none. Success is announced the system's way: the host moves focus to the heading of whatever it opens (a tabindex="-1" heading, as Tutorial Modal does), which makes a screen reader read it. Errors use the shipped Danger Toast unchanged; the Toast keeps its own role="status", which is part of Toast's contract and not something this variant adds. Focus stays where it was.
Keyboard path errorsWhen the Upload button's picker returns a bad file, the same Toast appears. Its "Choose a file" action is a real button, reachable in the Toast as usual.
ContrastTitle (Neutral-9) and hint (Neutral-5) on the veil (about Neutral-2) pass AA, at roughly 6:1 for the hint. The Obsidian dashes pass 3:1. The Red border and icon on Neutral-2 are about 3.3:1, which passes the 3:1 bar for UI graphics, and the invalid reason is also spelled out in Neutral-9 text.
MotionAn opacity fade only, off under reduced motion. The spinner stops under reduced motion.
Forced coloursCanvas veil, CanvasText borders and text, dotted border while invalid.

Tokens, reused patterns and literals

Reused

  • FileUploader: drag-over border (--border-width-md dashed --color-obsidian), fill (--color-neutral-2), --radius-lg; .c-uploader-hint; .c-uploader-row / -kind / -name / -size.
  • Type: --text-h5-* for the title (the source's h5), caption via the shipped hint.
  • Icons: --icon-lg, Tier 2 Fill for the expressive icon, Tier 1 Regular for the spinner.
  • Spacing: --spacing-16 inset, --spacing-24 target padding, --spacing-8 message gap, --spacing-4 above the row.
  • Colour: --color-red for invalid (Toast Danger's tone), --color-neutral-3 for the settled frame, Neutral-9 / Neutral-5 text.
  • Motion: --duration-fast + --ease-standard (the Command brief scrim's pairing), --duration-ambient linear for the spinner (Search input's recipe).
  • Shipped components: Toast (Danger) for errors, Button for the keyboard path, .sr-only for the hidden file input.

Decided, open and what this replaces

Decided (recommendations)

  1. A FileUploader variant, .c-uploader-page-drop, named for the shipped .c-uploader prefix. It adds only the full-surface layer, the veil and the enter/leave behaviour; everything visual inside comes from FileUploader.
  2. Scope: detect on the whole window, aim at the main pane. The veil covers everything, and the drop is accepted anywhere. The dashed target centres on the Content region via --c-uploader-page-drop-start. .is-contained covers a single region when a host needs that.
  3. A light veil, not the Modal scrim. The veil is 88% Neutral-2, with no blur. The target uses FileUploader's Obsidian drag-over border instead of the source's Neutral-5.
  4. Robust drag handling: Files only; drags that start inside the page are ignored; the layer catches the pointer and its children don't; a depth counter, plus a relatedTarget shortcut where it is reliable; a 1000ms dragover watchdog; Escape and a hidden tab also reset it. Window dragover and drop always call preventDefault on Files drags, so a file never opens.
  5. Invalid while dragging is best effort (count and known MIME, where readable), with dropEffect = "none". Everything is checked again on drop.
  6. Brief rules: one file, PDF / Word / PowerPoint, up to 25 MB. Failures go to the shipped Danger Toast with "Choose a file". Copy is in the Validation table.
  7. Hand-off is a host callback. onDrop(file) returns a promise; the layer shows "Reading the brief…" with the shipped file row until it settles. The host moves focus to the heading of what it opens.
  8. One path in. The visible "Upload a brief" Button calls the same take(), and it is required on every page that uses the layer. No second inline drop zone on the same page.
  9. Accessibility: the layer is aria-hidden, never focusable, and adds no live regions. The layer is off while any Modal, Tutorial or sheet is open.
  10. Motion: an opacity fade over duration-fast, and nothing at all under reduced motion. In forced colours the veil is opaque Canvas, borders are CanvasText, and invalid is dotted.

Open questions

  1. Light veil or the dark Modal scrim? This draft uses a light veil, because the page isn't blocked for a decision and the target is drawn for a light surface. The dark scrim would match Modal, but it would need white text and a white dashed border, which no FileUploader state has.
  2. Where should drop errors appear? This draft uses the Danger Toast, which stays until dismissed. The other option is an inline error under the page's "Upload a brief" button, which would need a new error state there. Is the Toast's own built-in announcement acceptable under the "no live regions" rule?
  3. Which files can Collab AI actually read, and how big? PDF, Word and PowerPoint up to 25 MB is a guess. Should emails (.eml / .msg), plain text or scanned images count as briefs?
  4. Several files at once: reject them (as drafted), take only the first, or read them together as one brief?
  5. Should FileUploader itself be fixed alongside this? That means the same type, size and error rules, a real button and file input inside its zone so a keyboard can reach it, and the icon-size mismatch. This would be a separate change, but this variant leans on it.

What this replaces

On Sales Home: the page-local drop layer from drop-layer.js and its markup and styles in the shared script (scan #17, stood in by .k-droplayer / .k-dropstage), and the file checks at the start of brief-import.js. The rest of brief-import.js, which reads the brief with Collab AI and opens the start sheet, stays with the host as the onDrop callback. The start sheet itself is scan #16 (a Modal variant), not part of this.
