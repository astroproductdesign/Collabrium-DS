What changed, and why

  • Bug fix — model dropdown was invisible. Root cause: the menu was position:absolute inside .c-prompt-bar-more, and that element has its own overflow:hidden — required for the Floating bar's collapse-to-0fr morph animation to actually hide its second row rather than just fading it. Opening the menu upward tried to render outside that box and got silently clipped: it wasn't broken math, the menu was positioned correctly and simply invisible. This is the exact same failure Chat window's own More options menu already hit and solved (documented in its own Anatomy section: "the thread is a scroll container, and a clipped ancestor clips a position: absolute descendant too") — same fix applies here: position:fixed, with right/bottom set in JS from the trigger's own getBoundingClientRect() at open time. Fixed-position elements escape all ancestor clipping, which is the whole point. Also switched the open/close JS from a single-instance querySelector to a delegated, multi-instance-safe handler (matching the rail-toggle's own established pattern) — needed now that up to four model switchers can exist on one page (two standalone Inline swatches, two Chat window composers).
  • Desktop/mobile comparison, all four items. Expanded and Collapsed each get a real 375px iframe for mobile (their breakpoint is @media-based, so it needs a genuine narrow viewport, not a narrow div — the iframe now takes a ?state= param so each gets its own small frame instead of one long scrolling one). Inline's mobile column is a plain 375px div, no iframe — it was already width:100% in flow and needed nothing special. New: Chat window itself, side by side at desktop and a real 375px shell width — its single-column breakpoint is a @container query on the shell's own size, so a plain narrow wrapper div triggers it directly, no iframe needed. Both Chat window instances are fully interactive (pillar filter, conversation switching, message actions, Jump to present, rail-toggle drawer, send) — the underlying script was refactored from a single hardcoded set of element ids into a small initChatWindowInstance(ids) function called once per shell, so two independent instances can coexist on one page without id collisions; the rail-toggle and message-actions wiring already worked this way (delegated by class, not id) and needed no change.
  • Not touched this round: the 406×46 resize and the Inline toolbar's More options icon both carry over unchanged from before. Still not demoed anywhere: the real scroll-driven collapse and the click-to-launch-Chat-window FLIP fold for the Floating bar — unrelated to today's fix/request, flagging again since it hasn't moved.
