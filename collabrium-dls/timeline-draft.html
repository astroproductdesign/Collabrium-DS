Draft · New component · Lists family

Timeline c-timeline

Shows a sequence of events or steps in order, connected by a line: campaign phases, project milestones, approval flows and deliverable schedules. Based on MUI Timeline, extended for Collabrium with status, a horizontal orientation, three sizes (S / M / L) and presets. Activity history stays in Lists (Activity Log); step-by-step forms stay in Stepper.

Recommendation

Ship Timeline as a new component, .c-timeline, in the Lists family, not as an extension of Lists' .c-list-timeline. Reuse Lists' avatar, bones, section header and footer as they are. Timeline has no number dots and doesn't reuse Stepper's indicator.

  • Why not extend .c-list-timeline: that's a line drawn through the leading slot of Activity Log rows, which have row padding, dividers and a trailing slot. Timeline needs a three-column grid (opposite, line, content), mirrored and alternating positions, a horizontal mode and connectors that change colour and dash with status. Building it on .c-list-item means overriding its layout, which is restyling.
  • How it relates to Activity Log: Activity Log answers "what happened, who did it", newest first. Timeline answers "what's the plan, where are we", oldest first, with a status on every step. Both docs should link to each other. On promotion, rename Lists' "Timeline" subsection to "Timeline line (Activity Log)" (proposed; see the side-by-side section below).
  • Why not Stepper: Stepper is a control for a multi-page flow (a form, onboarding) driven by one currentStep. Timeline is read-only content with seven statuses, rich content, slots and dates. Decided: no number dots. Numbered steps imply a step-by-step flow, which is Stepper's job, so Timeline doesn't offer a number dot type and doesn't reuse .c-step-indicator.
  • Reused as shipped: avatar dots are .c-list-item-lead.is-avatar; skeletons are .c-list-item-bone; month groups are .c-list-subheader; "Show more" footers are .c-list-footer; empty and error are Empty state .c-empty.is-section. None of them is restyled. Timeline only sets --c-list-lead on its own wrapper, and draws the current ring on its own positioner.
  • Accent for current: Obsidian. Stepper's Active step and Lists' selected row both use Obsidian, and brand colours classify departments (Component Rule 2), so Navy or Orange would read as "belongs to Water/Fire", not "now".

Alignment decision. The spec says both "Dot aligns with the first line of the Heading" and "Content top aligns with the dot centre". They can't both hold with a 32px dot, because the heading would hang 16px below the dot's top. Timeline keeps the first rule: the dot's centre sits on the centre of the heading's first line, at every size and dot type. Opposite text uses the same centre line. The example above is size L.

Why these steps. The heading steps once (body2 → body1, S/M → L), and the description steps once the other way (body2 → caption, M → S). So each size differs from its neighbour by one type change, plus dot size and gap. Caption, opposite and connector (2px) don't change. M gap 16: half-way between 12 and 24, and equal to card padding, so an M timeline in a card has an even rhythm. M glyph 14 (icon-micro): the same glyph-in-24px pairing as Lists' S icon chip; 16px in a 24px circle crowds the edge and the current ring. Default M (decided): it matches Lists' heading and S leading, the component a timeline usually sits next to. Class names: .c-timeline-sm/-md/-lg follow Button's component-level sizes. Lists' .is-s/.is-l size one element (its leading slot); Timeline's size is a whole-list choice, like its other list classes. dotType × size: plain works at every size (always 12px); icon and avatar need M or L. No number dots at any size.

Rules

  • Markup: a Button Ghost sm .c-timeline-details-toggle ("Details" + an .sr-only " for {heading}" so every toggle has a unique name) with aria-expanded + aria-controls, then a .c-timeline-details panel with hidden. Collapsed by default. Focus stays on the toggle. No live region.
  • Chevron: ph-caret-down (Tier 1 Regular) rotates 180° over --duration-fast. Under reduced motion it doesn't animate; it flips instantly, so the open state still shows.
  • Where it goes: always after the body, inside .c-timeline-content, never inside a link or button body. On a clickable item it sits below the clickable box (second example), so the box stays one target and the toggle is a second, separate one.
  • Details vs Show more: Show more un-clamps text that's already there (the description is part of the summary, just long). Details reveals extra, secondary content that isn't part of the summary at all: comments, version history, files, notes. An item can have both; Show more comes first.
  • Panel: Neutral-2, radius-sm, spacing-12 padding, body2 text, a caption semibold label, file chips in a list. Lines up with the body text in interactive timelines too.
  • Sizes: M and L. Not S: S is for dense lists (12px gaps, caption descriptions), and a nested panel breaks that rhythm. If an S item needs more, make it clickable and open a panel.
  • Targets: 44px on coarse pointers (transparent ::after). Forced colours: the panel gets a 1px CanvasText border.

    Accessibility

    Rules

    • Ordered list: <ol role="list">, one <li> per item, labelled by its visible heading.
    • Decorative parts: the separator (dot + connector) is aria-hidden. The opposite column is too; its text is repeated as .sr-only in the body, so a link's name includes the date.
    • Status is spoken once: from the visible status word (.c-timeline-status) or Badge. An .sr-only ", completed / upcoming" is added only when nothing visible says it. The one exception is ", current", which is always added: VoiceOver doesn't reliably announce aria-current on an <li>.
    • Current: aria-current="step" on the <li>, exactly one per timeline. Selected (open in a panel) is aria-current="true" on the body.
    • Keyboard: Tab only reaches clickable bodies, "Show more" and "Details" toggles and footer buttons. No aria-label on bodies; the name comes from the visible text (2.5.3).
    • Focus: 2px Obsidian ring, inset, plus a Neutral-2 fill (Lists). The component never moves focus: "Show more / less" and the footer toggles keep it. The host moves it only after Retry (to the heading as the skeleton goes in, or to the error title if it fails again). No live regions.
    • Targets: clickable bodies are at least 44px tall on coarse pointers; sm and md buttons (footer, Show more, slot buttons) get a transparent ::after to reach 44px.
    • Motion: the pulse runs only under prefers-reduced-motion: no-preference, three times in about 4s (under WCAG 2.2.2's 5s), then rests as a static ring. It grows by outline-offset, so it never causes sideways scroll. Shimmer stops under reduce.
    • Headings: keep them short. They clamp at 2 lines and, unlike descriptions, can't expand.
    • Contrast: heading Neutral-9; description, caption and opposite Neutral-5 (6.9:1 on white, 6.1:1 on the Neutral-2 hover). Status-colour caveats are under Item status.

    Forced colours

    • Filled dots become CanvasText discs with Canvas glyphs; outlined dots (upcoming, blocked, dotFill outlined) are CanvasText rings; skipped is a GrayText ring; current is a Highlight disc with a Highlight ring and pulse.
    • Connectors: CanvasText, current Highlight, upcoming and skipped GrayText. They are borders, so solid against dashed survives.
    • forced-color-adjust:none is set only on Timeline's own marks and connectors, never on the dot wrapper: it inherits, and would restyle a reused Lists avatar. Avatars need nothing extra: Lists already borders them in forced colours.
    • Status always survives through the glyph and the status word or Badge text. Colour is never the only signal.
    • Body: hover = 1px CanvasText outline, focus = Highlight, selected bar = Highlight. Bones and the file chip get a 1px CanvasText border.

    Do and don't

    Do

    • Order oldest → newest for plans. Newest first only when the user picks it.
    • Keep exactly one current item.
    • Pair every status colour with a glyph, a status word or a Badge. With plain dots, put the status word in the caption.
    • Put the date in the opposite column or the caption, never both.
    • Group long spans by month or phase with a Section header (.c-list-subheader).
    • Collapse or paginate past ~20 items.
    • Pick the size by context: M in cards (default), L on overview pages, S for dense schedules.
    • Keep headings short; they clamp at 2 lines and can't expand.
    • Use Show more for a long description, and Details for extra content (comments, files, history) that isn't part of the summary.
    • Give the timeline a width when it sits in an auto-sized flex or grid item (it's a size container and collapses otherwise).
    • Use Activity Log (Lists + .c-list-timeline) for who-did-what history.

    Don't

    • Mix dot types in one timeline (status glyphs replacing icons are fine).
    • Number the dots. For a numbered step-by-step flow, use Stepper.
    • Use icon or avatar dots, or Details, in S.
    • Put a date in two places: use a content date (above or below) or the opposite column, never both.
    • Make the dot or the line clickable, or nest a button or link inside a clickable body.
    • Strike through skipped steps; say "Skipped".
    • Use Timeline for a multi-page form (Stepper) or an activity feed (Activity Log).
    • Use horizontal for more than ~6 items, or combine it with a position class.
    • Colour text with status colours (no red or green text); status colour lives in the dot, connector and Badge.
    • Restyle .c-list-item-lead to fit; wrap it instead.

    Tokens, one-offs and deviations

    Tokens

    Colour: Neutral-1/2/3/4/5/8/9, Obsidian, Green, Amber, Red. Spacing: 4, 8, 12, 16, 24, 32, 40, 48, 60. Shape: --radius-sm, --radius-pill, --border-width-sm, --border-width-md. Type: heading at --weight-semibold (current --weight-bold): body2 at S/M, body1 at L; description: caption at S, body2 at M/L; caption for caption, opposite and file chip at every size; label3 size for the M avatar-badge glyph. Icons: --icon-micro, --icon-sm. Motion: --duration-instant, --duration-fast, --duration-ambient, --ease-standard. No new tokens.

    One-offs

    • 96px opposite width (2 × spacing-48; the spec's "e.g. 96px").
    • 2px content line gap (Lists' shipped literal).
    • 44px coarse min-height; 6px / 2px ::after button extensions (footer, Show more, slot buttons).
    • Pulse: 1.5 × --duration-ambient, 3 runs (~4s, CTA beacon's count), 0.6 → 0 opacity, outline grows 6px.
    • Avatar-badge glyph 11px at M / 12px at L (Regular, below icon-micro); badge overhang = a quarter of the badge.
    • .c-timeline-file static file chip (Input Chip container recipe, no ×).
    • Clamps 2 (heading) / 3 (description).
    • Not one-offs (tokens): item gaps 12 / 16 / 24, block bones 40 / 48 / 60, the 16px interactive gap and 8px body padding.

    Deviations from the spec

    1. Dot centre on the heading's first line, not "content top at dot centre".
    2. Current = heading 700 + Obsidian dot + ring + 3-run pulse (~4s) + spoken "current".
    3. Skipped = "Skipped" word, no strikethrough.
    4. Horizontal falls back to vertical under 600px; no side scroll.
    5. Mobile rules use the timeline's width (container query), not the viewport.
    6. Opposite stacks above the heading under 400px, and always in alternate / alternate-reverse (the far side of the line stays empty).
    7. density replaced by size (S / M / L, default M). Icon and avatar 24px at M, 32px at L; S is plain only. No number dot type (the spec lists one): use Stepper.
    8. Partial connector's remainder is Neutral-4 dashed; non-partial current is Obsidian dashed.
    9. dotFill only applies to items without a status.
    10. Plain-dot items must state status in the caption; a status word appears once (caption or Badge).
    11. Opposite is aria-hidden + .sr-only copy in the body.
    12. aria-current="step" on the <li>; selected = aria-current="true" on the body.
    13. Interactive slots only on static items; "Show more" sits outside the body.
    14. Empty and error use Empty state (section) with a Primary action, not Lists' compact list states, because the spec's empty state has an action.
    15. Interactive timelines use a 16px line → content gap (spec: 12px), and every body gets 8px inline padding so mixed items align.
    16. "Show earlier" / "Show more" are toggles that stay in place; focus never moves to an item.

    Decided

    • No number dots. Numbered steps imply a step-by-step flow, which is Stepper's job. Timeline doesn't reuse .c-step-indicator, so Stepper's state model and doc-vs-CSS questions don't apply here.
    • Medium is the default size.
    • Interactive gap: the 16px gap and 8px body padding switch on automatically via :has() when any body is clickable; .c-timeline-interactive forces it.
    • File chip: .c-timeline-file stays a one-off for now.
    • Green / Amber contrast: fine for now, because status is always carried by a glyph or a word. A dark check on Green is a separate future change for Stepper and Timeline together.
    • Month groups: the line ends cleanly at the last item of each group; no stub runs into the next header.
    • No spinner on the current item: it keeps the ring and the short pulse.
    • Roadmap preset: added (by quarter, a Tag per item for its type, M, icon dots, date above).
    • Alternate + opposite: the date sits above the heading on the content's side, never on the far side of the line; the opposite column is for right / left only.
    • Date positions: only two remain, (a) above and (d) below (date first in the caption, before the status). The inline start / end options are removed. Dates always come first. (a) above is the no-class default (the title markup is enough; .c-timeline-date-above is an optional alias); (d) below, .c-timeline-date-below, is for dense lists and lists with Badges.
    • "Due" wording: unfinished items with a single date read "Due 30 Oct" (overdue: "Due 15 Oct · Overdue"); completed and skipped show the plain date ("9 Oct · Done"); date ranges stay plain. Applies to both date positions and the opposite column. Approval Flow keeps "14 Oct · Approved" / "Waiting".
    • Card widget pattern: adopted as a documented composition recipe (no new class apart from .is-end).
    • Roadmap type labels: the shipped Tag (.c-tag). Badge = status, Tag = type.
    • Details at S: not supported; an S item that needs more opens a panel.
    • Lists rename: Lists' "Timeline" subsection becomes "Timeline line (Activity Log)" in DESIGN-SYSTEM.md on promotion.
    • Stepper doc fix: the shipped Obsidian-filled active step is correct; the Stepper doc text is corrected on promotion.
