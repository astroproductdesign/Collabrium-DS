# Changelog

All notable changes to @collabrium/ui. Dates are YYYY-MM-DD.

## Unreleased

### Next.js server rendering
- Fixed: importing `@collabrium/ui` into a Next.js page no longer fails the build with "createContext is not a function". Components that render on the server (Back button, Campaign card, ElementBadge, Lists, Stat card, Stepper) now take their icons from Phosphor's server-safe entry, and the Checkbox, Radio and App Shell contexts are client modules.
- Tested end to end: a fresh Next.js 15 app, set up as `CLAUDE.md` says, builds and renders a dashboard (App Shell, SidebarNav, PageHeader, Stat cards, Card, Table, Badge, Button).
- Docs: pages that use the components start with `'use client';` (icons are passed as components), the logo files are copied into the app's `public/`, and the docs site runs with `npm run playground:dev`.

### Get started
- New: the Get started page (first under Foundation, and first on the home page), in three steps: download and unzip, give your agent the prompt, and ask the design team for anything missing. Setting up without an agent is folded away beneath them.
- New: `npm run setup` in the folder installs, builds and packs it in one go.
- New: `CLAUDE.md` is now the guide for AI agents building with the system, and `AGENTS.md` is the same file for other AI tools (refreshed with every download build).
- Changed: install the packed file (`npm run setup`, then `npm install ../collabrium-dls-v2.0/collabrium-ui-0.1.0.tgz`), not the folder, so your app doesn't load React twice. README updated to match.
- Changed: the download leaves out the maintainer-only files (`MIGRATION-LOG.md`, review drafts and preview pages).

### Project folder
- Renamed: the project folder is now `collabrium-dls-v2.0` (was `collabrium-ui`), and so is the Download zip (`collabrium-dls-v2.0.zip`). The package is still `@collabrium/ui`.

### Foundation pages
- New: Brand Foundation (name, positioning, tone, voice and content rules), Photography (coming soon), Accessibility (the WCAG 2.1 AA targets and the rules every component follows) and Tokens (CSS variables, Tailwind v4 and JSON, each with Copy and Download).
- New: a Licensing table on Fonts.

### Illustration (Foundation)
- New: the Illustration foundation page and the illustration files. The 51 Audience characters (stills and 4-second loops), the reference image, `characters.json` and the characters bible now live in `playground/public/illustrations/`. Browse by category or search, hover to play a loop, and download a still or a loop.

### Tabs
- Fixed: tabs with counts no longer widen the page when the row scrolls sideways.

### Time picker
- New: `TimePicker` (designed from scratch; not yet in the DLS). Type any time (12:03 PM) or pick one from a list, every 15 minutes by default; one time, or a start and an end with each option's duration. 12-hour by default, 24-hour by prop; values are `HH:mm`. Also `formatTime` and `parseTime`.

### Timeline
- New: `Timeline`, Stepper's read-only plan view. Items with seven statuses (completed, current, upcoming, overdue, at risk, skipped, blocked), joined by a line that follows each status; plain, icon or avatar dots; S / M / L; the date above, below or opposite; right, left, alternate or horizontal, each following the timeline's own width. Clickable items, Show more, Details, partial lists and loading. `TimelineFile` for file chips. An item's `step` keeps "Step n of total" right in a filtered list; the docs show the Card widget recipe.

### Date picker
- Fixed: today inside a selected range. Mid-range it no longer breaks the band with a square box (it keeps the band, with its rounded outline on top), and as the range's start it no longer leaves a thin white line in the band.

### Compare modal
- New: `CompareModal`, two to four ad formats side by side: one column per format, nine facts in order, the highest published benchmark marked "Highest", then Export PDF, Export Excel and "Send to a media plan". The labels and the format row stay put while the table scrolls both ways. Opens from the Action bar's Compare and swings out of it. In the Modals group, which is now complete.
- Media Ad Modal and Metrics modal: a cancelled closing animation can no longer leave the page held.

### Metrics modal
- New: `MetricsModal`, the detail view a Metrics card opens into: the media and headline size on a sticky side, the title and category, every bar of the breakdown (growing in), where the audience lives, what it reads about and related items, with Add and "Use in a media plan". Two columns above a 640px panel. Every data-specific string comes from `labels`. Closing returns focus to the card for the item showing. In the Modals group.
- Media Ad Modal: its layer, head and related tiles are shared with Metrics modal (no change in behaviour).

### Media Ad Modal
- New: `MediaAdModal`, the detail view a Media Ad Card opens into: media, name and family, six spec cells (never blank), supported sizes drawn to one scale, the benchmark, industries and "Also consider", with Compare, Live demo and "Use in a media plan". It swings out of the card and folds back into it; ← and → step through the list; the page is held still while it is open. In the Modals group.
- Modal: the page hold is shared with Media Ad Modal (no change in behaviour).

### Tutorial Modal
- New: `TutorialModal`, a numbered walkthrough. A spotlight rings one part of the page at a time and a 340px card grows out of it; Back and Next move through the stops. The page is locked while it runs; the ×, Escape or the scrim end it. The card docks to the bottom at 767px and below.

### Chart color mapping
- New: the DLS guideline as functions in `@collabrium/ui/charts`: `categoricalColors(n)` (the seven series colours in order, dashed from the 8th), `sequentialColors(element, n)`, `divergingColor(value, extent, midpoint?)`, `divergingColors(n)` and `chartChrome`. Its page sits under Charts in the sidebar.
- Every Chart.js chart: a dashed series' legend marker is a short dashed line, so it can be told from the solid series of the same colour.

### Docs site
- Modals is now a group, like Charts: Modal / dialog and Tutorial Modal are its parts, with Compare modal, Media Ad Modal and Metrics modal as Coming soon. The Modal thumbnail shows the whole panel.
- The Charts overview's cards show each chart as a bare shape: no axes, gridlines, labels, legend or "View as table" button, like Charts (extra)'s. `ChartThumbnail` (in `@collabrium/ui/charts`) does it.
- Every page now fits a 320px phone screen; before, each was about 50px wider. Below 480px the top bar takes the content's 16px gutter and drops its Download link (the home page keeps its own), and the product name can shorten with an ellipsis. The anatomy tree indents 12px per level on phones, and its condition badges may wrap rather than run past the screen.
- A preview wider than its box (a 280px card on a phone) now scrolls inside the box instead of widening the page.
- Every card picture (home, Motion, Charts (extra), AI Native) is the same 152px box, and what it shows is scaled to fit it (`ThumbFit`), so no preview spills out of its card. Card-layout previews are tinted cards with no text on a fixed canvas.
- The bigger AI Native components (Chat window, Permission Prompt, Tool approval, Task Rows) show outline pictures on their cards; the five hooks (useMousePosition, useReducedMotion, useScrollProgress, useStagger, useWebHaptics) show looping outline pictures. Both are CSS only and still under reduced motion.
- The docs pages fill the width between the sidebar and "On this page" (no 1200px cap; paragraphs keep their 68-character line length), and each example sits in its own tinted panel.
- Preview files for Motion batches 3 to 5 now render every example from their docs file.

### Changed
- Modal takes `size="lg"`: a 760px panel (`--measure-prose`) for a form or record with several fields on desktop, with the body scrolling between a pinned header and footer. Default size unchanged. Added at the user's request; not in the DLS.
- Tokens synced to DLS v0.9.132: adds `--color-navy-deep`, `--color-canvas-warm-card-hover`, `--color-navy-text`, `--nav-rail-width`, `--nav-rail-tile` and the Illustration tokens (`--ill-ink`, `--ill-paper`, `--ill-accent`, `--ill-tint`, `--ill-tile`, `--ill-tile-sm`). `tokens.ts` gains an `illustration` group, and `layout` gains `navRailWidth` and `navRailTile`.
- Card: a list card's (`padding="list"`) header now sits 16px from the top and its footer 16px from the bottom, so titles line up with neighbouring cards. `CardHeader` takes an `action`: one control at the end of the title row, such as a borderless Dropdown.
- Empty state: an inline empty state inside a Card no longer adds its own padding or centres itself; its text sits 16px in, like the card's other content.
- Input field takes `type="otp"` (in review): a 6-digit one-time code in six boxes (48px, shrinking to 40px on a narrow phone) over one real input with a numeric keyboard and SMS autofill (`autocomplete="one-time-code"`). Digits only, paste fills from the start, never masked; `onComplete` fires on the sixth digit and the field never submits the form. Input field's label, helper, error, success, required and disabled.
- Input field takes `type="password"` (in review): the browser's dot masking and a show/hide toggle (Eye / EyeSlash, Regular, named "Show password" or "Hide password", with a 44px hit area, disabled with the field) at the end of the box, which keeps 40px clear at every size. Edge's own reveal button is hidden. A password offers no success check, trailing icon, prefix or suffix. There is no separate Password field component.
- Card takes `padding="list"` for a card whose body is a List: 8px top and bottom, no side padding, the rows running edge to edge (a CardHeader or CardFooter keeps 16px at the sides).
- Card spread, Card carousel, Card cover flow and Card time machine take a `size` (`sm`, `md`, `lg`: 0.75, 1 and 1.25 of the designed size) and shrink to fit the space they are in; the piece takes up its scaled size, so nothing hangs outside it.
- `body` now sets body1 (16px / 22px / 500). Charts: gridlines are 1px on both engines, and marks draw in over `--duration-reveal` (Chart.js `easeOutQuart`, Recharts `ease-out`), with reduced motion still off. Bars take 60% of their category (capped at 24px, or 20px horizontal); vertical bar charts (Bar, Stacked bar, Waterfall, Candlestick, Composed) give every category a 40px slot and scroll sideways when they do not fit, with the value axis fixed in place; axis numbers shorten (500k, 1.2M) while tooltips show the full value, tooltips are per category for line, area and bar charts and per point or slice for the rest, and the legend swatch is 12px.

### Added
- **Page hero** (in review; not in the DLS, ported from Workdesk's project hero at the user's request). `PageHero`: the tinted title block at the top of a page about one subject. A Water-bg to Water-bg-strong gradient, a 96px ink-doodle illustration tile (20 motifs by name, including new `calendar`, `bell` and `people`), a status pill with a toned dot and a meta line, the h1, a description, Secondary actions on the right and an optional 4px progress bar with an h3 percentage. 16px padding and a 64px tile under 640px.
- **Charts** (in review). The Chart.js set is now a Charts group, like Charts (extra): `BarChart` (vertical or horizontal), `StackedBarChart`, `LineChart`, `AreaChart`, `MixedChart`, `DoughnutChart`, `PieChart`, `PolarAreaChart`, `RadarChart`, `ScatterChart`, `BubbleChart` and `SparklineChart` in `@collabrium/ui/charts`, each taking data rather than a Chart.js config, with the DLS chrome and colours and a "View as table" view. `ChartCard` titles a chart and fills it; `ChartGrid` sets cards 3, 2 or 1 across. `setupCharts()` no longer throws when it first runs, and styles radar and polar area axes.
- **Notes** (in review). `Notes`: coloured notes pinned to one record in a table or list, up to four, coloured by position (orange, pink, green, navy). A pin, or a tilted stack of 2 to 4 that straightens on hover, with an add button. Hovering shows the notes as a list; a click opens a panel that grows out of the pin, anchored to the row: a 2 × 2 grid of notes, or one note in its own colour with Resolve (or Reopen), Edit and delete; new and edited notes are written straight onto the note. Escape, a click outside or scrolling closes it. At four notes the add buttons grey out and say why.
- **Action bar** (in review). `ActionBar`: floats at the bottom of the page while the reader has a selection, says how much is selected and offers the actions for it. User select (people, as an avatar stack: 4 then "+N"; Cancel, Save to a list, Create new list; an optional AI shimmer) and Item select (2 to 4 removable chips, names cut at 15 characters; Clear and Compare, which waits for a second pick). It rises and fades in, centres over the content (`--cui-action-bar-inset-start`), goes to two rows with small buttons when it's 640px or narrower, keeps Back to top and toasts above it, and moves focus sensibly when a pick is removed or it leaves. `ActionBarSpacer` lets the last row scroll clear of it.
- **App Shell** (in review). `AppShell`: the frame every screen sits in. The warm canvas, the SidebarNav inset 16px from the window, and the content region beside it (a `<main>`, the only part that scrolls) with the page header in `header`, 48px above the content; `width="reading"` centres it at 1200px, `backToTop` adds Back to top. Below 1024px the nav is collapsed to its rail; on phones it floats over the content as a card. `ContentGrid` and `ContentGridItem`: 4 columns, boxes spanning 1 to 4, each row as tall as its tallest box, one column on phones. SidebarNav inside App Shell is collapsed below 1024px, and `sidebarNavInitScript` takes `{ appShell: true }`. Docs site: the Mobile width switch now also tells App Shell it is on a phone.
- **SidebarNav** (in review). `SidebarNav`: the app's main navigation. A 240px rail with the logo (from the DLS logo library, passed in), a Department strip (sliding highlight, hover card, coming-soon departments, sideways scrolling past 6), grouped items with counts, "Soon" items and one level of children, and a footer with the account menu (opens upward). Collapses to a 72px icon rail with hover labels and count dots, remembered with `collapsedStorageKey` (`sidebarNavInitScript` stops a flash); a content-sized card on phones. The docs site's sidebar now uses it.
- **Filters** (in review). `Filters`: a bar above a table or list. An optional search box, then a named trigger per dimension (Tiered exposure's "More filters" past about 8, or one Compact "Filter" trigger), each opening a checkbox panel that applies only on Done; applied triggers turn Obsidian with a count. The applied values show as removable chips in a tray underneath ("+N" past 5, Clear all). `filtersToSearchParams` and `filtersFromSearchParams` keep it in the URL. Chip's input chips take an optional `removeLabel`.
- **FileUploader** (in review). `FileUploader`: a drop zone with one "Choose" button, then a row per file. It checks each pick or drop against the page's rules (type, empty, size, already added, count, total) and reports every rejection in one message under the zone; good files are handed over at once (`onAccept`). The page shows each upload through `files`: progress (or a sliding bar), done ("Uploaded"), or failed with Try again. Rows can offer Preview and Download in a "More actions" menu; images can show a thumbnail. One file (once it's in, the zone says "Drop a new brief to replace it" and the button "Replace file") or many (past five, "Show N more"), full, read-only and disabled; stacks and centres when under 480px wide.
- **Date picker** (in review). `DatePicker`: a field on Input field's box that opens a month calendar. Pick one date (it closes), or a range (`mode="range"`: a start, an end, then Apply; Cancel keeps the old one). Today has an outline; days outside `min` / `max` or `isDateDisabled` are greyed out. Works from the keyboard (arrows, Home / End, PageUp / PageDown); the calendar floats over the page, above the field when there's no room below. Values are `YYYY-MM-DD` strings. Dates read day first ("12 Jul 2026"), weeks start on Monday, and a range is one band. Press the month or the year in the header (plain text, not dropdowns) to pick from a grid of months or years (newest first), so a birthday is a few presses away.
- **Back to top** (in review). `BackToTop`: a small round button in the bottom-right corner that appears once you have scrolled past 480px (hiding again under 240px, so it never flickers) and scrolls back to the top, smoothly unless reduced motion is on. It reads the window and an optional scrolling region (`scrollRef`), rises above an open Action bar, and can be lifted above a permanent bottom bar with `--cui-back-to-top-bottom` on `<html>`. Toasts now sit 12px above it while it shows. When the page scrolls inside a frame, it steps in past that frame's scrollbar. After the click, keyboard focus moves to the page's main heading.
- **Pagination** (in review). `Pagination`: the footer under a table or list. Under 10 pages, "Showing 41–60 of 116" and numbered pages (with "…" past 7 slots); from 10 pages, Prev, a page select, "of 77", Next and an optional Rows per page. Hides itself when everything fits on one page; on phones, "3 of 6" between Prev and Next. The count stays (greyed) while the next page loads. Rows per page (`onPageSizeChange`) shows in both layouts, so a bigger page size never leaves you stuck; pressed buttons look like hover, as Button. Tool approval's step count now uses Pagination's indicator. The page and Rows per page pickers are the library's Dropdown, not the browser's own select. Dropdown's open list is no longer cut off by a card, table or preview box that hides its overflow.
- **Table** (in review). `Table`: rows and columns of data, standalone (its own bordered surface) or embedded (inside a Card). Every column sorts (click or Enter on the header); opt-in checkboxes with a bulk toolbar, always-visible row actions, rows that open, frozen first and last columns with edge shadows when it scrolls sideways, a loading skeleton after 300ms, an empty state, a sticky header and column priority. On phones it keeps 600px and scrolls. The docs site's props, keyboard and motion tables now use it. A total row (a column's `total`, under the body, "Total" in the first column, light grey) is added here; it isn't in the DLS. Low-priority columns hide first (at 1024px), then medium (at 768px). The frozen columns' edge shadows, the sticky header's shadow and the selected row's left line now actually show (the DLS's box-shadows are never drawn on table cells).
- **Toast** (in review). `ToastProvider` and `useToast()`: transient feedback in the bottom-right corner (a full-width band on phones). Four tones, a title and / or a message, one link action and a close. Up to 3 at once with the rest queued; each leaves after 5 seconds (Danger stays until closed), pausing while hovered or focused; Escape closes the focused one. Each new toast is read out by screen readers. `Toast` on its own draws a static one.
- **Slider** (in review). `Slider`: drag to pick one value, or a range with `variant="range"`, on native range inputs. An Obsidian fill on a Neutral-3 track, a 20px thumb that lifts on hover and drag, a value tooltip over the moving thumb, optional min and max labels or a static value, compact and disabled. `format` (number, RM, percent) writes every value the same way, and screen readers hear it. A range's thumbs never cross, and a click on the track moves the nearer one. The label matches Input field's (14px), the tooltip's sides match Tooltip's (12px), and on touch screens the rail is 44px tall.
- **Stat / KPI card** (in review). `StatCard` and `StatGrid`: a dashboard tile for one metric on Card's surface, with a label, the value, a trend against a period, an icon chip, a description, a footer and a sparkline slot; negative values, one hero tile per row, Secondary tiles (smaller value, a unit, a goal rail with its achieved line) and an Interactive tile that opens what's behind the metric. `StatGrid` fits as many 180px columns as the row allows, equal height.
- **Quantity selector** (in review). `QuantitySelector`: a number field with − and + for whole-number quantities, on Input field's box with Button ghost buttons. Type it, press or hold the buttons, or use ↑ ↓, PageUp / PageDown and Home / End; typed values are checked on Enter or blur and refused with a clear message, never clamped. Units ("1 spot", "2 spots") and a currency prefix, comma thousands, a box that never changes width, compact and type-only, read-only with a lock and its reason, disabled.
- **Radio card** (in review). `RadioCardGroup` and `RadioCard`: a group of large cards where the whole card is one radio option, on Card's surface with Radio's circle: a title, an optional badge, a description and a meta line pinned to the bottom. One column, then straight to two (or three with `columns={3}`). Hover, selected, focus on the whole card, disabled with the reason in the meta, and Radio group's required and error.
- **Dropdown** (single and multiple select; in review). `Dropdown`: a trigger on Input field's box that opens a panel of options to pick one, or with `multiple`, to tick any number: Checkbox's box in each row, "N selected" in the box, an optional Select all row (`selectAll`) and a Clear / Done footer. Options can be grouped under headings (`group`), in both. Outlined or borderless; default, hover, open, filled, disabled, read-only and error; searchable; options with an icon or avatar, a description and a meta note; empty and loading panels; opens above when it doesn't fit below. A combobox and listbox with the full keyboard: arrows, Home / End, Enter, Escape, Tab and type-ahead.
- **Search input** (in review). `SearchInput`: a search box with a leading magnifying glass and a clear (×) once there is text. Default searches in place (with a loading or "No matches found" panel); User Search and Item Search open a list of results to pick one from (↓ ↑, Enter, Escape, or the mouse) and collapse to the choice (avatar, name, role) in the same 48px box (the DLS's 40px left the selected row cramped). Error, disabled, selected and selected — disabled.
- **Lists** (in review). `List` and `ListItem`: a vertical run of same-shaped rows, each with a Leading slot (icon chip, avatar, thumbnail or logo at 24, 32 or 48), Content (a heading, a description and a caption with an optional icon or status dot; rich two-line headings for activity) and Trailing (a value, a badge, a checkbox or switch the whole row toggles, a button, or a chevron on link rows). The row is a link, a button, a label or static by its props; selected (`current`), disabled, hover, pressed and an inset focus ring. Dividers, an Activity Log timeline, an on-page `bleed`, skeleton rows (`ListItemSkeleton`) in a `busy` list, `ListSection` day headers (sticky), and `ListEmpty`, `ListError` and `ListFooter`.
- **Segmented Control** (in review). `SegmentedControl`: 2 to 5 equal-width segments on a Neutral-2 track, all text (uppercase caption) or all icons (with a tooltip naming each); the selected one sits on a white pill that slides and resizes to it (placed without sliding on first render, jumping under reduced motion). Default and compact sizes, a disabled option or a disabled control. A `radiogroup` of `radio`s; ←/→, Home and End move focus, Space or Enter selects.
- **Tabs** (in review). `Tabs`: in-page section switching, a full-width row of tabs over a 1px track, the active one Neutral-9 with a 2px Obsidian inset underline; optional Regular icon and a count (hidden at 0, "99+" past 99); hover, pressed, focus and disabled from Button Ghost. The row scrolls sideways when the tabs don't fit, with a 32px fade on the edge that hides tabs. Panels sit 16px below and cross-fade (at once under reduced motion). ←/→, Home and End move between tabs. The docs site's Preview / Code tabs now use it. `scrollButtons` adds left and right arrows at the edges of an overflowing row for mouse users; `surface="canvas"` matches the fades to the warm page canvas.
- **PageHeader** (in review). `PageHeader`: the page-level title block, flush in the layout: an h1 title (32/38), an optional body2 subtitle 8px under it, and an optional right-aligned row of actions 8px apart. A real `h1` by default (`headingLevel` 2 or 3 for a panel). Back button's docs now show it under the real PageHeader.
- **Back button** (in review). `BackButton`: the one control above a Level 2+ screen's page header that goes one level up, named for the parent screen ("← Reports"), as a real link (`href`) or button (`onClick`). Ghost at rest, Neutral-2 on hover, Neutral-3 pressed, the Obsidian focus ring; its own row sits 12px above the page header.
- **Stepper** (in review). `Stepper`: an ordered list of steps whose states all come from one `currentStep` (Completed: a green check; Active: an Obsidian numbered disc and a bold label; Upcoming: an outlined number), with Error on the current step and Warning on a completed one as flags whose message takes the description's place. Horizontal, with equal connectors whatever the labels, or vertical with fixed 16px ones; below 480px of its own width a horizontal stepper hides descriptions and truncates labels. Each step is read as "Step 2 of 4: Profile, current step".
- **Modal / dialog** (in review). `Modal`: one decision in a 400px panel over the Neutral-9 56% scrim: a title (h4 look, a real heading that names the dialog), the real Button as the close X, the body, and a footer of Secondary then Primary above a divider. Fades in and out on `--duration-fast`, and holds the page still while open (no scrolling, the rest of the page `inert`). Opens with focus on the title; Tab stays inside; Escape, the X or a scrim click closes it, and focus returns to what opened it.
- **ElementBadge** (in review). `ElementBadge`: a 32px chip marking which element owns an item, with the element's Fill glyph (flame, mountains, drop, scales, plant) on a 12% tint of its colour; alone it carries the element's name as `title`, and `showLabel` adds the name (uppercase eyebrow) over its function ("Visibility & Energy") or a `sublabel`.
- **Progress Bar** (in review). `ProgressBar`: read-only progress, determinate single (Obsidian by default; Complete green, Error red or a department colour only when passed), stacked (department colours, or Purple, Turquoise and Neutral-4 for general data, a Neutral-3 remainder and a legend) and indeterminate (a looping shimmer; a still bar under reduced motion). Compact, default and large tracks; a header row, trailing or inside-the-fill label. Grows in from 0 on mount. Media Ad Card's skeleton shimmer and Metrics card's bars now use it instead of their own copies.
- **Metrics card** (in review). `MetricsCard`: a Media Ad Card for an item whose figures matter most (audience segments, influencers, channels), on the same shell. At rest the tagline (3 lines) and a size line naming the top bar; Live, a headline total and up to five bars that grow in, staggered, with "+N more", an empty bar's dash and "No breakdown on file". An Add toggle (the A key) with Compared's look, an optional clip that plays only while Live, a reserved two-line title, a capped category Tag, `audienceCategoryTags`, and `MetricsCardSkeleton`. Media Ad Card's shell is now shared internally.
- **Media Ad Card** (in review). `MediaAdCard`: one ad format as a gallery tile, an `<article>` with a full-bleed 16:10 media slot (the placeholder unless you pour media in), a round Compare toggle (`aria-pressed`, the C key), the name as a button stretched over the card, the fixed-colour family Tag, an optional Built-for-this-slot Badge, and a body that trades its tagline for the Objective, Sizes and Benchmark rows when the card goes Live on hover, focus or a first tap. Compared, an optional pointer tilt, and `MediaAdCardSkeleton` for loading.
- **Hero Card** (in review). `HeroCard` in four states: Default (an h2-sized eyebrow, a two-line heading, optional media and next-step line, a Ghost CTA, an optional Fire-orange corner ribbon), Risk (Fire tint, orange border), AI (Dark) (Neutral-8, Amber eyebrow, a Secondary CTA, a pointer tilt on hover) and Selected (the bigger detail with an AI Recommendation Info Banner, a source line and a Primary CTA). `CommandBrief`: the Selected content as a dialog that swings up over a scrim, closing panel-first. `onOpen` makes the card's heading a button over the card, so the brief opens from the keyboard too.
- **Info Banner** (in review). `InfoBanner`: an inline notification at the top of a section or card, in six tones (Neutral, Info, Success, Warning, Danger, and AI Recommendation with Prompt input bar's moving pastel wash and ring), a Fill icon, one message, up to two underlined actions, and a close button when dismissible (`role="status"`; persistent banners are `role="note"`). Slides down and fades in; on dismiss it slides up, fades and closes its space. Built before Hero Card, which uses it.
- **Entry Card** (in review). `EntryCardSet` and `EntryCard`: a set of "start here" tiles, each one real button (or link) with a decorative media slot, a title, a one-line hint and a chevron. Character (a figure rising above the card, still and clip, placeholder shipped) and Artefact (an 84px tile with one of five drawings: brief, research, idea, package, deck) variants, one per set. The set's own width sets 1, 2, 3 or 5 columns; character sets reserve width-scaled headroom.
